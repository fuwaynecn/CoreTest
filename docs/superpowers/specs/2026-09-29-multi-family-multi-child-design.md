# 多家庭多孩子支持与五六年级题库补齐设计

- 日期：2026-09-29（同日修订 v2：纳入校历自动解锁、五六年级题库一次性补齐）
- 状态：设计已确认，尚未实施
- 范围：
  1. 在现有家庭数学训练系统（math.fubee.cn）上支持多个互相独立的家长家庭，每个家长账号下管理多个孩子，各孩子拥有独立的年级与题库设置。
  2. 按人教版教材一次性补齐五、六年级缺失的知识点与题目。
  3. 引入校历轴：系统按学期时间自动解锁知识点，家长可手动覆盖。

## 1. 背景与目标

### 1.1 现状

- `users` 表用 `role`（parent/child）区分身份，所有用户共享一张表。
- 登录 API 按角色取唯一一个用户（`WHERE role = ? LIMIT 1`），没有登录名，全家只靠一个密码进入。
- `parent_preferences` 以 `child_id` 为主键，隐含「一个家庭、一个孩子」。
- 题库（`question_templates` / `question_instances`）全局共享，无年级概念；题目难度只有 1–4 的相对等级。
- `ai_provider_configs` 为全局唯一配置。
- 各业务表（训练会话、掌握状态、奖励、证据、复习计划等）均通过 `child_id` 关联到用户。
- 知识点现状：阶段 2 有 38 个，阶段 1 有 3 个（其中 `decimal` 与阶段 2 同 id 合并），库内实际 40 个知识点。
- 覆盖现状（按人教版对照）：五年级数与代数主线（小数、方程、分数加减）覆盖较好，几何与综合实践约缺一半；六年级只覆盖分数、比、百分数，圆、负数、比例、圆柱圆锥等核心单元全部缺失。
- 供给约束（2026-09-23 题库供给死锁教训）：每个知识点至少需要 6 个以上不同题干模板，才能支撑每日约 20 题、7 天不重复偏好的出题需求。

### 1.2 目标

1. 平台支持多个互相独立的家长（多个家庭），家长之间数据隔离，只能看到自己名下的孩子。
2. 一个家长账号可管理多个孩子（一对多）；同一家庭的多位长辈共用该家长账号。
3. 孩子拥有独立账号，自行登录做题。
4. 全局题库保持单份，不做孩子级副本；每个孩子的可用题目由「年级 + 校历进度 + 家长覆盖」共同决定。
5. 按人教版一次性补齐五、六年级缺失知识点；每个知识点配足题目供给。
6. 系统按校历自动解锁本学期已教到的知识点；家长可提前开启或强制关闭，并可恢复自动。
7. 家长账号采用手动开户，不做开放注册。
8. AI APIKEY 保持全局共用。

### 1.3 非目标（YAGNI）

- 不引入 family 家庭表，不支持多家长账号归属同一家庭。
- 不做孩子级题库副本，题目不按孩子复制。
- 不做家长注册页面、邀请码注册流程。
- 不把 AI 配置改为按家长隔离。
- 本期不补齐一~四年级题库内容（数据结构已预留年级，内容以后另立项）。
- 不支持人教版以外的教材版本（北师大版、苏教版单元顺序不同）。
- 不做自动年级晋升（每年由家长手动修改孩子年级）。
- 不覆盖学前、初中年级（现有 equation-l6 等超纲内容保留，但不作为小学考核要求）。

## 2. 数据模型变更

在现有表上做最小增量。

### 2.1 users 表新增列

| 列 | 类型 | 说明 |
|----|------|------|
| `login_name` | TEXT UNIQUE | 登录名；家长、孩子各自全局唯一 |
| `parent_id` | TEXT → users.id | 仅孩子行有值：指向所属家长 |
| `grade` | INTEGER | 仅孩子行有值：1–6 年级 |
| `is_admin` | INTEGER DEFAULT 0 | 仅家长行：是否管理员 |

约束：

- `parent_id` 为 NULL 或引用 `users.id`；删除家长时其下孩子的处理策略见 2.5。
- `grade` 为 NULL 或 BETWEEN 1 AND 6。
- `is_admin` IN (0, 1)，仅对 parent 角色有意义。

### 2.2 skills 表新增列

| 列 | 类型 | 说明 |
|----|------|------|
| `grade` | INTEGER NOT NULL | 知识点所属年级（1–6） |
| `semester` | INTEGER NOT NULL | 1=上册，2=下册 |
| `expected_week` | INTEGER NOT NULL | 该知识点在学期中约第几周学完（1–20） |

约束：

- `grade` BETWEEN 1 AND 6；`semester` IN (1, 2)；`expected_week` BETWEEN 1 AND 20。
- 一个知识点唯一归属「一个年级 + 一个学期」；跨学期的同一主题拆成两个知识点（见 4.2）。
- 题目（template/instance）通过所属 skill 继承年级与学期，题目表本身不加这两列。

### 2.3 新增 child_skill_settings 表

孩子对知识点的三态覆盖设置：

```text
child_skill_settings
  child_id    TEXT → users.id
  skill_id    TEXT → skills.id
  mode        TEXT NOT NULL DEFAULT 'auto'   -- auto / on / off
  updated_at  INTEGER NOT NULL
  PRIMARY KEY(child_id, skill_id)
```

语义：

- 无记录 = `auto`（跟随校历自动解锁），新增知识点、添加新孩子均不需要灌数据。
- `on`：家长提前强制开启（即使校历尚未教到）。
- `off`：家长强制关闭（即使校历已教到）。
- 家长切换状态时对该行做 upsert；「恢复自动」将该行 mode 改回 `auto`（不删除行，保持唯一写入路径）。

### 2.4 新增 academic_calendar 校历表

```text
academic_calendar
  school_year      TEXT PRIMARY KEY        -- 如 '2026-2027'
  semester1_start  TEXT NOT NULL           -- 'YYYY-MM-DD'
  semester2_start  TEXT NOT NULL           -- 'YYYY-MM-DD'
  updated_at       INTEGER NOT NULL
```

- 由管理员家长维护，每年更新一行（下学期开学日期随春节变动）。
- 找不到当前学年行时：使用内置默认（上学期 9 月 1 日、下学期 2 月 22 日），并在家长后台提示管理员补录。

### 2.5 删除与保留策略

- 删除孩子：本期不提供家长自助删除孩子功能（避免误删历史数据）；孩子停用通过后续运维处理。
- 删除家长：运维操作，删除前必须先处理其名下孩子。
- 题库模板/实例、校历表的全局管理仅管理员可做。

### 2.6 不改动的部分

现有业务表（`training_sessions`、`session_items`、`attempts`、`mastery_states`、`mastery_evidence`、`reward_events`、`review_schedules`、`dosage_states`、`diagnostic_runs`、`learning_plans`、`parent_preferences` 等）的 `child_id` 外键与结构一律不动。

## 3. 账号与开户

### 3.1 家长开户（手动）

- 提供运维脚本 `scripts/create-family.ts`，在服务器上通过 `docker exec math-trainer node scripts/create-family.ts` 运行。
- 入参：家长登录名、显示名、密码；创建 `role=parent, is_admin=0` 的账号。
- 新家庭开户由 Wayne 执行；无任何公开注册入口，公网陌生人无法注册。
- 脚本负责校验登录名唯一、密码走现有 `hashCredential` 流程。

### 3.2 孩子账号（家长自助）

- 家长登录后在「孩子管理」中点「添加孩子」：填写孩子姓名、登录名、年级（1–6）、密码。
- 系统创建 `role=child, parent_id=当前家长, grade=所选年级` 的账号。
- 家长可随时重置孩子密码、修改孩子年级与显示名。
- 每年 9 月开学由家长手动调整孩子年级，系统不自动晋升。

### 3.3 登录

沿用现有两个入口，仅增加「登录名」输入框：

- 家长入口：登录名 + 密码 → `/parent`
- 孩子入口：登录名 + 密码 → `/child`
- 登录 API 从「按角色取唯一用户」改为「按角色 + 登录名取用户」，再走现有 `verifyCredential` 校验。
- 会话结构（`auth_sessions`）、角色守卫（`requireRole`）、登录后跳转逻辑保持不变。

## 4. 人教版题库补齐

### 4.1 缺口范围

按人教版教材对照，拟新增约 13 个知识点：

五年级：

- 五上：位置（数对）、植树问题；多边形面积补平行四边形与梯形（向现有 area skill 加模板）。
- 五下：因数与倍数、图形的运动（旋转）、找次品；长方体/正方体补表面积与容积（向现有 volume skill 加模板）；分数的意义与性质（向现有分数 skill 加模板）。

六年级：

- 六上：位置与方向、圆、扇形统计图、数与形。
- 六下：负数、百分数应用（折扣/成数/税率/利率）、圆柱与圆锥、比例（正反比例与比例尺）、鸽巢问题。

### 4.2 跨学期主题拆分规则

一个 skill 只能归属一个年级+学期，以下现有 skill 需拆分，存量模板按内容重新指向新 skill：

- `decimal`：四年级下册小数加减 与 五年级上册小数乘除拆分。
- `fraction`：五年级下册（意义、性质、加减）与 六年级上册（乘除、分数应用题）拆分。
- `percent`：六年级上册（百分数认识）与 六下（折扣、税率、利率）拆分。

拆分后最终知识点总数约 53–56 个，以《人教版知识点目录与进度表》为准。

### 4.3 内容供给要求

- 每个知识点（含新增）至少 6 个不同题干模板，全库新增模板预计约 80–120 个。
- 新模板必须通过 `formal-template-validation`：从渲染后的中文题干反推答案的锚定规则校验。
- 题目继续保持全局单份；内容编制顺序建议先五年级、后六年级，但本期一次交付。

## 5. 校历自动解锁引擎

### 5.1 自动解锁规则

输入：孩子年级、当前日期、当前学年的 `academic_calendar`。

「开学至今周数」= 今天与学期开始日相差天数 ÷ 7，向下取整（开学当天为第 0 周）。

对每个知识点计算 `auto_available`：

1. `skill.grade < 孩子.grade` → **true**（低年级学过的内容始终保留用于复习）。
2. `skill.grade = 孩子.grade`：
   - 上册：`开学至今周数 >= skill.expected_week`（以 semester1_start 起算）。
   - 下册：`开学至今周数 >= skill.expected_week`（以 semester2_start 起算）。
   - 处于学期结束后的暑假期间 → 该年级全部 true。
3. `skill.grade > 孩子.grade` → **false**。

### 5.2 家长覆盖后的最终状态

```text
mode = off  → 禁用
mode = on   → 启用
mode = auto → auto_available
```

### 5.3 出题流程变化

每日组题 scheduler 在现有选题逻辑之前，先按 5.1/5.2 求有效知识点集合，再选题：

```text
候选知识点 = skills，其最终状态为「启用」
```

其后的到期复习优先、7 天不重复偏好（已改为偏好+回退）、模板/实例调度等逻辑保持不变。

诊断（diagnostic）出题范围同样应用该过滤，保证诊断只考查孩子已经学过的内容。

## 6. 家长端界面与权限

### 6.1 家长首页

`/parent` 改造为孩子卡片列表。每张卡片显示：孩子姓名、年级、今日训练状态、成就摘要。卡片提供：

- 「学习情况」：该孩子的报告、错题、掌握状态；进入后的页面顶部提供孩子切换条。
- 「题库设置」：该孩子的知识点列表，按学期与教学顺序分组，每行可设置「自动 / 提前开启 / 关闭」，并显示当前实际状态（已解锁/未解锁）；覆盖项提供「恢复自动」。
- 「孩子管理 / 添加孩子」：创建新孩子账号、修改年级与密码。

### 6.2 管理员专属区

- 题库编辑（题目为全局内容，普通家长改动会影响所有家庭）。
- 校历表维护（每学年开学日期）。
- AI 服务配置（全局共用一份）。

### 6.3 权限分层

| 功能 | 管理员家长（is_admin=1） | 普通家长 |
|------|:---:|:---:|
| 添加/管理自己的孩子 | ✅ | ✅ |
| 查看自己孩子的学习情况 | ✅ | ✅ |
| 配置自己孩子的知识点三态覆盖 | ✅ | ✅ |
| 进入题库编辑题目（全局） | ✅ | ❌ |
| 校历表维护 | ✅ | ❌ |
| AI 服务配置（全局共用） | ✅ | ❌ |

### 6.4 安全要求

- 所有涉及孩子数据的 API 必须校验 `child.parent_id === 当前登录家长 id`；不满足时返回 403（页面场景可重定向）。
- 普通家长无法通过修改 URL、请求参数访问别家孩子。
- 题库编辑、校历维护、全局 AI 配置的 API 必须校验 `is_admin=1`。
- AI 配置继续使用现有加密存储方式，配置本身保持全局唯一一份。

## 7. 现有数据迁移

1. 现有家长：`login_name='admin'`、`is_admin=1`。
2. 现有孩子：`parent_id` 指向现有家长；`login_name`、`grade` 由 Wayne 在迁移前提供。
3. 执行《人教版知识点目录与进度表》：现有 skills 回填 grade/semester/expected_week；新增约 13 个知识点；decimal/fraction/percent 拆分并把存量模板重新指向新 skill。
4. 写入新模板（80–120 个），全部通过形式化校验。
5. `academic_calendar` 写入当前学年行（默认 2026-09-01 / 2027-02-22，待 Wayne 确认）。
6. `child_skill_settings` 初始不灌数据（无记录即 auto）。
7. 题目、会话、作答、奖励等历史数据原样保留。
8. 上线前对生产库副本做一次迁移演练，沿用现有备份机制（/opt/math-trainer/backups）。

## 8. 测试策略

### 8.1 单元测试

- 登录名 + 密码登录成功/失败；登录名不存在、角色不匹配的分支。
- 校历解锁引擎：开学周边界（expected_week 前一周/当周）、上下学期切换、暑假全解锁、低年级恒解锁、高年级恒锁定。
- 校历缺行时使用默认日期并给出提示。
- 三态覆盖：auto 跟随、on 提前开启、off 强制关闭、恢复自动。
- 拆分映射：存量模板全部指向合法新 skill，无悬空引用。
- 越权访问：家长访问非名下孩子返回 403。
- 管理员权限：普通家长无法访问题库编辑、校历维护与 AI 配置。

### 8.2 迁移测试

- 在生产库副本上执行迁移：现有孩子 `parent_id`、`grade` 正确；所有 skill 都有合法 grade/semester/expected_week；每个知识点模板数 ≥ 6；历史数据行数不丢失。

### 8.3 端到端测试

- 家长添加孩子（选年级）→ 孩子登录 → 只看到校历已解锁范围内的题。
- 家长提前开启下学期知识点 → 该知识点可出题；强制关闭已解锁知识点 → 不再出题；恢复自动后行为回到校历。
- 管理员更新学期开学日期 → 解锁结果随之变化。
- 普通家长与管理员分别登录，入口与页面权限符合 6.3。
