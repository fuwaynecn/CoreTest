# 多家庭多孩子支持设计

- 日期：2026-09-29
- 状态：已确认（设计阶段，尚未实施）
- 范围：在现有家庭数学训练系统（math.fubee.cn）上支持多个互相独立的家长家庭，每个家长账号下管理多个孩子，各孩子拥有独立的年级与题库设置。

## 1. 背景与目标

### 1.1 现状

- `users` 表用 `role`（parent/child）区分身份，所有用户共享一张表。
- 登录 API 按角色取唯一一个用户（`WHERE role = ? LIMIT 1`），没有登录名，全家只靠一个密码进入。
- `parent_preferences` 以 `child_id` 为主键，隐含「一个家庭、一个孩子」。
- 题库（`question_templates` / `question_instances`）全局共享，无年级概念；题目难度只有 1–4 的相对等级。
- `ai_provider_configs` 为全局唯一配置。
- 各业务表（训练会话、掌握状态、奖励、证据、复习计划等）均通过 `child_id` 关联到用户。

### 1.2 目标

1. 平台支持多个互相独立的家长（多个家庭），家长之间数据隔离，只能看到自己名下的孩子。
2. 一个家长账号可管理多个孩子（一对多）；同一家庭的多位长辈共用该家长账号。
3. 孩子拥有独立账号，自行登录做题。
4. 全局题库保持单份，通过年级与知识点开关实现每个孩子独立的题库范围。
5. 覆盖小学 1–6 年级：知识点标注年级，题目继承。
6. 家长账号采用手动开户，不做开放注册。
7. AI APIKEY 保持全局共用。

### 1.3 非目标（YAGNI）

- 不引入 family 家庭表，不支持多家长账号归属同一家庭。
- 不做孩子级题库副本，题目不按孩子复制。
- 不做家长注册页面、邀请码注册流程。
- 不把 AI 配置改为按家长隔离。
- 不覆盖学前、初中年级。

## 2. 数据模型变更

在现有表上做最小增量。

### 2.1 users 表新增列

| 列 | 类型 | 说明 |
|----|------|------|
| `login_name` | TEXT UNIQUE | 登录名；家长、孩子各自全局唯一 |
| `parent_id` | TEXT → users.id | 仅孩子行有值：指向所属家长 |
| `grade` | INTEGER | 仅孩子行有值：1–6 年级 |
| `is_admin` | INTEGER DEFAULT 0 | 仅家长行：是否管理员 |

约束：

- `parent_id` 为 NULL 或引用 `users.id`；删除家长时其下孩子的处理策略见 2.4。
- `grade` 为 NULL 或 BETWEEN 1 AND 6。
- `is_admin` IN (0, 1)，仅对 parent 角色有意义。

### 2.2 skills 表新增列

| 列 | 类型 | 说明 |
|----|------|------|
| `grade` | INTEGER NOT NULL | 知识点所属年级（1–6） |

约束：`grade` BETWEEN 1 AND 6。题目（template/instance）通过所属 skill 继承年级，题目表本身不加年级列。

### 2.3 新增 child_skill_settings 表

孩子的知识点独立启用设置：

```text
child_skill_settings
  child_id    TEXT → users.id
  skill_id    TEXT → skills.id
  enabled     INTEGER NOT NULL          -- 0/1
  updated_at  INTEGER NOT NULL
  PRIMARY KEY(child_id, skill_id)
```

语义采用「缺省即启用」：

- 表中没有记录的知识点默认启用。
- 家长切换开关时一律对该行做 upsert：关闭写 `enabled=0`，重新开启写 `enabled=1`；代码只保留这一条写入路径，不做删除行操作。
- 该设计使新增知识点、添加新孩子都不需要批量灌数据。

### 2.4 删除与保留策略

- 删除孩子：本期不提供家长自助删除孩子功能（避免误删历史数据）；孩子停用通过后续运维处理。
- 删除家长：运维操作，删除前必须先处理其名下孩子。
- 题库模板/实例的全局管理仅管理员可做。

### 2.5 不改动的部分

现有十几张业务表（`training_sessions`、`session_items`、`attempts`、`mastery_states`、`mastery_evidence`、`reward_events`、`review_schedules`、`dosage_states`、`diagnostic_runs`、`learning_plans`、`parent_preferences` 等）的 `child_id` 外键与结构一律不动。

## 3. 账号与开户

### 3.1 家长开户（手动）

- 提供运维脚本 `scripts/create-family.ts`，在服务器上通过 `docker exec math-trainer node scripts/create-family.ts` 运行。
- 入参：家长登录名、显示名、密码；创建 `role=parent, is_admin=0` 的账号。
- 新家庭开户由 Wayne 执行；无任何公开注册入口，公网陌生人无法注册。
- 脚本负责校验登录名唯一、密码走现有 `hashCredential` 流程。

### 3.2 孩子账号（家长自助）

- 家长登录后在「孩子管理」中点「添加孩子」：填写孩子姓名、登录名、年级（1–6）、密码。
- 系统创建 `role=child, parent_id=当前家长, grade=所选年级` 的账号。
- 家长可随时重置孩子密码、修改孩子年级与显示名。

### 3.3 登录

沿用现有两个入口，仅增加「登录名」输入框：

- 家长入口：登录名 + 密码 → `/parent`
- 孩子入口：登录名 + 密码 → `/child`
- 登录 API 从「按角色取唯一用户」改为「按角色 + 登录名取用户」，再走现有 `verifyCredential` 校验。
- 会话结构（`auth_sessions`）、角色守卫（`requireRole`）、登录后跳转逻辑保持不变。

## 4. 年级与题库体系

### 4.1 知识点年级标注

- 38 个知识点按小学课程标准逐一标注年级，以迁移脚本数据文件形式落地。
- 实施时先产出《38 个知识点年级对照表》，部署前由 Wayne 确认；可按实际教材调整。
- 每个知识点必须有合法年级（1–6），不允许遗留空值。

### 4.2 孩子的题库范围

每个孩子可获得的题目由两个条件叠加过滤：

1. 年级过滤：知识点 `grade <= 孩子.grade`。
2. 家长设置：该孩子的 `child_skill_settings` 中无记录，或 `enabled=1`。

题目内容仍为全局单份，不做孩子级副本。

示例：

- 一年级孩子只可能得到一年级知识点的题。
- 三年级孩子可得到三年级及以下知识点的题；家长可在此范围内单独关闭某个知识点。

### 4.3 出题流程变化

每日组题 scheduler 在现有选题逻辑之前，先求候选知识点集合：

```text
候选知识点 = skills
  WHERE grade <= 孩子.grade
  AND (child_skill_settings 无记录 OR enabled = 1)
```

其后的到期复习优先、7 天不重复偏好（已改为偏好+回退）、模板/实例调度等逻辑保持不变。

诊断（diagnostic）出题范围同样应用该过滤，保证诊断只考查孩子学过的内容。

## 5. 家长端界面与权限

### 5.1 家长首页

`/parent` 改造为孩子卡片列表。每张卡片显示：孩子姓名、年级、今日训练状态、成就摘要。卡片提供：

- 「学习情况」：该孩子的报告、错题、掌握状态；进入后的页面顶部提供孩子切换条。
- 「题库设置」：该孩子的知识点开关列表，按年级分组展示；开关操作写入 `child_skill_settings`。
- 「添加孩子」：创建新孩子账号。

### 5.2 权限分层

| 功能 | 管理员家长（is_admin=1） | 普通家长 |
|------|:---:|:---:|
| 添加/管理自己的孩子 | ✅ | ✅ |
| 查看自己孩子的学习情况 | ✅ | ✅ |
| 配置自己孩子的知识点开关 | ✅ | ✅ |
| 进入题库编辑题目（全局） | ✅ | ❌ |
| AI 服务配置（全局共用） | ✅ | ❌ |

### 5.3 安全要求

- 所有涉及孩子数据的 API 必须校验 `child.parent_id === 当前登录家长 id`；不满足时返回 403（页面场景可重定向）。
- 普通家长无法通过修改 URL、请求参数访问别家孩子。
- 题库编辑、全局 AI 配置的 API 必须校验 `is_admin=1`。
- AI 配置继续使用现有加密存储方式，配置本身保持全局唯一一份。

## 6. 现有数据迁移

1. 现有家长：`login_name='admin'`、`is_admin=1`。
2. 现有孩子：`parent_id` 指向现有家长；`login_name`、`grade` 由 Wayne 提供（迁移脚本参数化）。
3. 38 个 skills：按已确认的年级对照表写入 `grade`。
4. `child_skill_settings` 初始不灌数据（缺省即启用）。
5. 题目、会话、作答、奖励等历史数据原样保留。
6. 上线前对生产库副本做一次迁移演练，沿用现有备份机制（/opt/math-trainer/backups）。

## 7. 测试策略

### 7.1 单元测试

- 登录名 + 密码登录成功/失败；登录名不存在、角色不匹配的分支。
- 知识点年级过滤：仅返回 `grade <= 孩子年级` 的知识点。
- 知识点开关：缺省启用、显式禁用、重新启用。
- 越权访问：家长访问非名下孩子返回 403。
- 管理员权限：普通家长无法访问题库编辑与 AI 配置。

### 7.2 迁移测试

- 在生产库副本上执行迁移：现有孩子 `parent_id`、`grade` 正确；所有 skill 都有 1–6 年级；历史数据行数不丢失。

### 7.3 端到端测试

- 家长添加孩子（选年级）→ 孩子登录 → 只看到年级范围内的题。
- 家长关闭某知识点 → 后续组题不再出现该知识点。
- 普通家长与管理员分别登录，入口与页面权限符合 5.2。

## 8. 开放事项（实施前确认）

- 现有孩子的登录名与年级：由 Wayne 在迁移前提供。
- 《38 个知识点年级对照表》：实施第一阶段产出并经 Wayne 确认。
