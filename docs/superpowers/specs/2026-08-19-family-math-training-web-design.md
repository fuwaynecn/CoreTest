# 家庭数学训练网页系统设计文档

- 日期：2026-08-19
- 状态：已确认
- 目标用户：一名即将升入小学六年级的学生及其家长
- 主要设备：孩子使用平板横屏，家长使用手机或电脑
- 使用范围：单个家庭

## 1. 背景与目标

学生目前数学成绩稳定在 85～95 分，基础并不薄弱，主要问题是读题不细、漏看条件、不审题以及笼统表现为“粗心”的失误。系统的目标不是简单增加刷题量，也不局限于海南当地某一版教材，而是以国家课程标准中的核心能力为主干，适当吸收浙江、湖北等地区常见的综合应用、数形结合、开放探究和思维训练方式。

系统需要形成一个可持续的家庭训练闭环：

> 诊断能力 → 制定计划 → 每日训练 → 记录过程 → 定位错因 → 自主订正 → 间隔复习 → 阶段评估 → 调整计划

第一版的成功标准不是覆盖尽可能多的知识点，而是让孩子能够连续使用六周，并在以下方面出现可观察的改善：

- 漏条件、答非所问和单位错误逐步减少。
- 基础计算准确率稳定，速度在不牺牲准确率的前提下自然提升。
- 对常见方程结构更加熟悉，能够从文字关系中列出方程。
- 遇到综合题时会主动标记条件、画图、估算和检查。
- 家长能够看到具体能力证据和可执行建议，而不只是一个总分。

## 2. 设计原则

1. **过程优先**：记录审题、草稿、提示、修改、检查和订正过程，不只记录最终答案。
2. **准确优先于速度**：准确率未稳定前不提高速度要求，不进行速度排名。
3. **确定性核心**：排课、客观题判分、掌握度和复习日期由可解释的规则决定，不交给 AI 决策。
4. **AI 可选**：未配置 API Key 时核心功能完整可用；AI 只增强提示、讲解和拓展。
5. **适量训练**：每项能力设置最低量、目标量和上限量，避免不会做时继续机械加题。
6. **逐步撤除支架**：孩子出现某类错误时增加审题提示，稳定改善后逐渐撤除提示。
7. **单家庭优先**：不为未来可能出现的机构、多家庭和付费场景增加当前复杂度。
8. **平板优先**：孩子端采用大字号、大点击区域和单任务界面，减少干扰。

## 3. 用户与身份

### 3.1 孩子身份

- 通过头像和简单 PIN 进入。
- 只能访问训练、订正、个人进步和积分页面。
- 无法查看或修改 API Key、训练规则及家长报告。

### 3.2 家长身份

- 通过密码进入。
- 可以查看能力地图、错因分析、周报、计划和题目证据。
- 可以调整训练天数、时长、休息日和专项方向。
- 可以配置 AI 服务、费用上限和数据导出。

第一版不开放公开注册，不包含多家庭、多孩子、付费或教师账号。

## 4. 训练周期与时间结构

默认训练频率为每周 5 天、每次约 30 分钟：

- 4 次常规训练。
- 1 次混合测评与错题复盘。
- 每 4 周进行一次阶段评估。
- 每 6 周重新确定下一阶段训练重点。

单次训练分为四段：

| 环节 | 默认时长 | 内容 |
| --- | ---: | --- |
| 旧知识唤醒 | 5 分钟 | 3～5 道间隔复习短题 |
| 核心训练 | 12 分钟 | 当日主知识点的示例与练习 |
| 审题专项 | 8 分钟 | 应用题、综合题及审题卡 |
| 订正回顾 | 5 分钟 | 1～2 道代表性错题及变式 |

训练时长是目标而不是硬性倒计时。到达上限时，系统保存进度并结束，不用额外题目惩罚未完成。

## 5. 知识体系与能力地图

系统不按单一教材章节组织，而是建立六个能力领域：

1. **数与运算**：整数、小数、分数、百分数、比、因数倍数、估算和简便计算。
2. **方程与代数意识**：字母表示数、等量关系、解方程、列方程和规律表达。
3. **图形与空间**：角度、周长、面积、体积、组合图形、切割拼接和空间想象。
4. **数据与统计**：表格、统计图、平均数、数据比较和简单可能性。
5. **应用与建模**：行程、工程、价格、比例、百分率及生活情境综合问题。
6. **数学思维与学习习惯**：审题、估算、画图、列表、分类、验证、表达、检查和反思。

每个知识点标记一个内容层级：

- 国家课程标准核心。
- 地区综合提升，体现浙江、湖北等地区常见的综合与探究风格。
- 小升初衔接与思维拓展。

地区提升内容使用原创题、已获授权内容或规则生成的同类题，不直接复制受版权保护的试卷。

### 5.1 能力状态

每个细分能力显示为以下状态之一：

- 尚未诊断。
- 需要补强。
- 正在学习。
- 基本掌握。
- 稳定保持。

状态判断综合使用：

- 首次作答正确率。
- 提示使用程度。
- 解题用时是否明显异常。
- 数天后能否重新做对。
- 改变数字、未知数位置或题目表述后能否完成。
- 能否说明关键关系或完成必要检查。

一次训练中连续做对不能直接升级为“稳定保持”。

## 6. 初始诊断

首次使用安排 3 次、每次约 25 分钟的适应性诊断：

1. 数与运算、分数、估算。
2. 方程、应用题、审题习惯。
3. 几何、数据、综合思维。

题目根据前序表现调整后续难度，但诊断不生成公开排名。诊断完成后生成：

- 初始能力地图。
- 主要错因分布。
- 首个六周训练计划。
- 算力、方程、审题和综合应用的初始训练剂量。

## 7. 题库设计

### 7.1 首批内容范围

第一版制作约 100～150 个经过人工审核的基础题型模板，覆盖：

- 四、五年级关键基础诊断。
- 小数、分数、百分数与比。
- 计算、简算和估算。
- 六级方程训练。
- 常见数量关系与综合应用题。
- 周长、面积、体积及组合图形。
- 原创地区综合提升题。

一个题型模板可以通过白名单规则替换数值、单位、情境和未知数位置，生成能够确定性校验的变式。

### 7.2 题目元数据

每道题或模板至少包含：

- 所属能力领域与知识点。
- 内容层级和难度等级。
- 运算步骤数量及数字复杂度。
- 题目阅读量及是否包含干扰信息。
- 常见错误类型。
- 预计完成时间。
- 适用作答方式：口算、笔算、选择、填空、列式或列方程。
- 标准答案、单位要求和确定性解题步骤。
- 可生成的安全变式范围。
- 来源、授权状态或原创标记。

### 7.3 判分边界

- 客观题、数值题、标准方程题由规则判分。
- 等价分数、小数精度、单位和方程等价形式采用明确的标准化规则。
- 开放性解释题可由 AI 提供建议，但不凭 AI 结果自动提高掌握度。
- 无法确定性校验的 AI 生成题只作为拓展内容，不能进入正式诊断或阶段测评。

## 8. 算力训练剂量

算力训练每天约 5～8 分钟，初始剂量为：

- 8～12 道口算或短计算。
- 3～5 道笔算或简算。
- 1～2 道估算或结果判断。

每周目标量约为：

- 40～60 道短计算。
- 15～25 道综合计算。
- 5～10 道估算与检查题。

难度梯度依次为：

1. 单一运算准确性。
2. 小数、分数基本运算。
3. 多步混合运算。
4. 运算律与简便计算。
5. 含未知数的运算。
6. 在应用情境中选择并完成计算。
7. 估算和反向检查。

只有在间隔开的两次训练中正确率均达到约 90%，且近期复习没有明显退步时，才提高复杂度。速度目标使用孩子自身历史中位数，不设置统一速度标准。

## 9. 方程熟悉度训练

方程训练分为六级：

1. 等式与天平意识。
2. 一步加减方程。
3. 一步乘除方程。
4. 两步方程。
5. 含括号、小数或分数的方程。
6. 从文字和实际问题中列方程。

每次安排 4～6 题，每周训练 3～4 次。初始每周约 15～20 题，熟练后减少同类重复，增加混合题和应用题。

每一级均包含：

- 直接解方程。
- 判断变形步骤是否正确。
- 补全缺失步骤。
- 根据数量关系列方程。
- 代入检查。

升级要求为：能够独立完成、不过度依赖提示、一周后仍能做对、表述变化后仍能识别结构，并能解释关键步骤。

## 10. 自动排课与间隔复习

每日任务默认按以下比例组成：

- 45% 当前最需要提升的能力。
- 25% 间隔复习。
- 20% 审题和综合应用。
- 10% 趣味或拓展内容。

初始复习间隔为 1、3、7、14、30 天。独立答对且能解释时延长间隔；依赖提示、答错或不能解释时缩短间隔。

每项能力设置：

- 最低训练量，保证持续接触。
- 目标训练量，满足正常熟练需求。
- 单次和每周上限，防止过度刷题。

同类题在一次训练中通常不超过 6 道。若仍未理解，系统停止继续加题，改为示例、分级提示、变式对比或建议家长介入。

排课引擎采用可测试的确定性规则。AI 不能修改能力状态、复习日期或训练比例。

## 11. 审题与纠错机制

应用题和综合题可以启用审题卡：

- 要求解决什么。
- 已知条件有哪些。
- 单位是否一致。
- 哪些信息有用。
- 数量关系是什么。
- 答案大约在什么范围。

系统按近期错误动态介入：

- 连续漏条件时，开启条件逐项确认。
- 单位错误增多时，提交前确认单位。
- 计算正确但答非所问时，要求重读最后一句。
- 结果明显不合理时，先要求估算。
- 同类错误稳定改善后，逐渐撤掉提示。

答错后按以下顺序提供帮助：

1. 定位性提醒。
2. 关键问题提示。
3. 半步提示。
4. 完整讲解。

孩子需要选择或确认错因：没看清问题、漏条件、单位错误、数量关系错误、计算错误、没有检查或知识点不会。系统可以建议错因，但不能把所有失误统一归为“粗心”。

## 12. 孩子端体验

### 12.1 今日首页

- 一个主要操作：“开始今天的训练”。
- 显示预计用时、四个训练环节、本周完成次数、积分和近期徽章。
- 显示一句具体目标，例如“今天重点读清问题和单位”。
- 不显示同学排名或复杂总分。

### 12.2 答题页面

- 单题大卡片布局。
- 支持标记已知条件、问题、单位和干扰信息。
- 提供平板手写草稿区，保存草稿供订正和家长查看。
- 提供适合题型的答案输入和分级提示。
- 只在需要时显示提交前检查，不对每道题重复打断。

第一版不要求自动识别全部手写公式。草稿可以保存为笔迹数据或图片，供回看；自动手写识别属于后续能力。

### 12.3 订正与结束页

- 先展示原作答和草稿，让孩子定位错误。
- 允许修改具体一步并完成一道小变式题。
- 结束页只显示今日完成内容、改进点、成功纠正的错误、积分和下次复习方向。

## 13. 家长端体验

### 13.1 首页与周报

首页直接回答：

- 本周是否按计划训练。
- 哪些能力在提升。
- 哪些错误反复出现。
- 家长当前需要做什么。

建议必须具体可执行，例如：“本周出现 3 次单位遗漏，今晚请让她口头复述一道题，不需要额外加题。”

### 13.2 能力地图与证据

每个知识点显示当前状态、首次正确率、提示依赖、近期保持情况和下次复习日期。家长可以展开查看形成判断的具体题目和作答过程。

### 13.3 错因与行为分析

单独追踪：

- 漏条件率。
- 答非所问次数。
- 单位错误。
- 计算错误。
- 未检查直接提交。
- 提示使用情况。
- 自主订正成功率。

### 13.4 计划管理

家长可以查看未来一周计划，调整训练时间和休息日，指定算力、方程或应用题专项，重新安排错题，并标记学校当前学习内容。

## 14. 轻量激励

积分主要奖励过程行为：

- 完成审题卡。
- 主动检查并发现错误。
- 少提示或无提示完成订正。
- 间隔一周后成功回忆。
- 清楚讲出数量关系。
- 按计划完成训练。

徽章示例包括“审题侦探”“单位检查员”“方程平衡师”和“估算能手”。

连续训练不会因偶尔休息全部清零。系统不设置同学排名、无限刷分或用答题速度兑换奖励。

## 15. AI 服务设计

### 15.1 配置

家长可以在服务端配置 OpenAI 或 DeepSeek：

- API 地址。
- 模型名称。
- API Key。
- 默认模型和备用模型。
- 单次、每日或每月调用上限。
- 是否允许生成拓展题。
- 是否允许分析文字解题过程。

未配置 API Key 时，系统使用预设提示和已审核讲解。孩子端不能读取或修改密钥。

### 15.2 允许的 AI 用途

- 将已审核解法改写成适合小学生的分级提示。
- 根据已确定的错因生成简短解释。
- 为已校验的题型生成情境变化或开放性拓展。
- 为家长生成基于结构化数据的周报草稿。

### 15.3 禁止的 AI 用途

- 直接决定客观题标准答案。
- 单独修改掌握度或排课计划。
- 将未校验题目加入正式诊断或测评。
- 根据开放性文本自动作出高风险教育结论。
- 接收孩子姓名等非必要身份信息。

## 16. 总体技术架构

系统采用一个全栈 Web 应用和一个关系型数据库：

- **孩子端**：平板优先的响应式网页和 PWA 安装能力。
- **家长端**：适配手机与电脑的管理页面。
- **应用服务**：身份验证、题库、排课、判分、报告、积分和 AI 代理接口。
- **关系型数据库**：保存用户、题目、作答、能力状态、计划和配置。
- **对象存储**：保存草稿图片及必要附件。
- **AI 适配层**：以统一内部接口连接 OpenAI、DeepSeek 或关闭 AI。

第一版保持单体架构，不引入微服务、消息队列、独立推荐服务或多租户框架。部署保持云平台可替换，核心业务规则不依赖特定云厂商。

### 16.1 核心数据流

1. 排课引擎根据能力状态和到期复习项生成今日任务。
2. 孩子完成审题、草稿和作答。
3. 服务端使用确定性规则判分。
4. 系统记录首次答案、修改、用时、提示、检查和错因。
5. 掌握度规则更新能力状态和下次复习日期。
6. 只有需要讲解或拓展时才调用 AI。
7. 训练结束后更新孩子反馈、积分和家长报告。

## 17. 核心数据实体

| 实体 | 主要职责 |
| --- | --- |
| User | 保存家长或孩子身份及安全凭据 |
| Skill | 定义知识点、能力领域、层级和依赖 |
| QuestionTemplate | 保存题型模板、答案规则、元数据和变式规则 |
| QuestionInstance | 保存一次生成后的确定题目与标准答案 |
| TrainingPlan | 保存六周目标和每周配置 |
| TrainingSession | 保存一次训练的环节、状态和时间 |
| Attempt | 保存首次答案、修改、用时、提示和判分结果 |
| ErrorTag | 保存标准错因及孩子或系统的确认信息 |
| MasteryState | 保存能力状态、证据和下次复习日期 |
| RewardEvent | 保存积分来源和徽章授予记录 |
| AIProviderConfig | 保存加密后的服务配置、限额和启用状态 |
| AIUsageLog | 保存调用类型、用量、费用估计和失败信息 |

数据库只保存实现训练目标所需的数据。第一版只有一个孩子，但数据模型仍明确区分家长和孩子身份，不采用散落在代码中的固定用户名。

## 18. 安全、隐私与数据保护

- 全站使用 HTTPS。
- 家长密码使用安全密码哈希保存。
- API Key 在服务器端加密保存，任何接口都不得把完整密钥返回浏览器。
- AI 请求使用内部匿名标识，不发送孩子姓名等身份信息。
- 家长可以导出训练数据和配置备份。
- 草稿及作答数据只有本家庭可访问。
- 服务日志对答案内容和密钥进行脱敏。
- AI 接口设置频率限制、超时和费用上限。
- 删除数据属于家长主动操作，需要二次确认并提供备份提示。

## 19. 故障与降级策略

- AI 未配置、超时或返回异常时，自动使用预设提示，不中断训练。
- AI 生成题校验失败时，退回已审核题库。
- 网络短暂中断时，在浏览器本地暂存当前作答，恢复后重试提交。
- 重复提交通过请求标识保证不会产生重复积分或重复能力更新。
- 当前训练无法继续时，保存已完成环节并允许稍后恢复。
- 题目配置错误时停止展示该题，记录问题并选择同能力的备用题。
- 数据库或存储异常时显示明确状态，不把未保存内容伪装成已完成。

## 20. 测试策略

### 20.1 单元测试

- 数值、分数、单位和方程等价判分。
- 题型模板变式约束及答案一致性。
- 训练剂量上下限。
- 1、3、7、14、30 天复习规则。
- 能力状态升级、降级和提示依赖规则。
- 积分防重复及徽章条件。

### 20.2 集成测试

- 从生成任务到作答、判分、订正和更新掌握度的完整数据流。
- 家长和孩子权限隔离。
- AI 配置、切换、限额、超时和预设提示降级。
- 网络重试与重复提交保护。
- 草稿保存、恢复和家长查看。

### 20.3 端到端测试

- 平板横屏完成一次完整训练。
- 家长通过手机查看周报、能力证据和错因。
- 完成三次诊断并生成六周计划。
- 无 AI 配置时完成全部核心流程。
- 配置任一 AI 服务后测试连接并获得分级讲解。

### 20.4 内容质量检查

- 所有正式题型模板在发布前人工审核。
- 自动生成一组边界变式并验证答案、单位和题意。
- 地区提升题检查原创性、年龄适配性和解法完整性。
- AI 输出使用长度、语气、答案泄漏和不当内容检查。

## 21. 第一版验收标准

第一版完成需同时满足：

1. 平板横屏能够完成约 30 分钟的完整训练。
2. 不配置 AI 时所有核心功能正常可用。
3. 配置 OpenAI 或 DeepSeek 后能够测试连接并获得分级讲解。
4. 能完成三次诊断并生成首个六周计划。
5. 算力和方程能依据准确率、提示使用和复习结果调整训练量。
6. 漏条件、单位错误、计算错误等能够分别记录和统计。
7. 答错后能够自主订正并安排后续变式。
8. 家长可以查看能力判断的具体证据。
9. 间隔复习规则能够按计划执行。
10. AI 失败、页面刷新或短暂断网不会丢失当前作答。
11. 核心排课、判分和题目变式通过自动化测试。
12. 孩子端和家长端关键流程通过平板及手机尺寸的端到端测试。

## 22. 明确不在第一版范围内的内容

- 多家庭、多孩子、学校、教师和机构管理。
- 公开注册、订阅、支付、排行榜和社交功能。
- 原生 iOS 或 Android 应用。
- 整页作业 OCR、复杂手写公式自动识别和实时语音老师。
- 由 AI 独立生成、判分并纳入正式掌握度的开放题。
- 与学校教务系统、第三方题库平台或家长社交平台集成。

## 23. 已确认的关键决策

- 第一版只供一个家庭使用，同时提供独立孩子端和家长端。
- 孩子主要使用平板，家长主要使用手机或电脑。
- 每周默认训练 5 天，每次约 30 分钟。
- 内容不局限海南教材，以国家课程标准为主干并加入地区综合提升。
- 学生当前主要改进方向是审题、读题、检查和减少非知识性失误。
- 题目采用已审核题库、规则变式和少量 AI 拓展的混合模式。
- AI 服务在配置 API Key 后启用，同时支持 OpenAI 和 DeepSeek。
- 系统部署在公网云端，核心逻辑保持云平台可替换。
- 激励采用轻量积分、连续训练和徽章，不采用强游戏化和同学排名。

## 24. 后续工作入口

本设计文档通过最终审阅后，下一步是制定分阶段实施计划。实施计划需要优先交付一个最小纵向闭环：身份进入、今日任务、一道题作答、确定性判分、订正、能力更新及家长查看证据；随后再扩展完整诊断、题库规模、积分和 AI 能力。
